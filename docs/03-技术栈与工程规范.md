### 3.4.2 一次性安装脚本

```bash
# 1. Go 工具链（Linux amd64 示例，arm64 换 linux-arm64）
curl -fsSLO https://go.dev/dl/go1.24.0.linux-amd64.tar.gz
sudo rm -rf /usr/local/go && sudo tar -C /usr/local -xzf go1.24.0.linux-amd64.tar.gz
echo 'export PATH=$PATH:/usr/local/go/bin:$HOME/go/bin' >> ~/.bashrc && source ~/.bashrc

# 2. Node 与 pnpm
curl -fsSL https://fnm.vercel.app/install | bash && source ~/.bashrc
fnm install 20.11.0 && fnm default 20.11.0
corepack enable && corepack prepare pnpm@9.12.3 --activate

# 3. protoc
PB=28.3
curl -fsSLO "https://github.com/protocolbuffers/protobuf/releases/download/v${PB}/protoc-${PB}-linux-x86_64.zip"
sudo unzip -o "protoc-${PB}-linux-x86_64.zip" -d /usr/local && protoc --version

# 4. Go 侧开发工具（等价于 make install-tools）
go install google.golang.org/protobuf/cmd/protoc-gen-go@v1.35.1
go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@v1.5.1
go install github.com/swaggo/swag/cmd/swag@v1.16.4
go install github.com/golangci/golangci-lint/cmd/golangci-lint@v1.61.0
go install go.uber.org/mock/mockgen@v0.5.0
go install golang.org/x/vuln/cmd/govulncheck@latest

# 5. 校验
make doctor
```

### 3.4.3 本地开发启动流程

```bash
git clone https://github.com/novapanel/novapanel.git && cd novapanel
make install-tools        # 安装 protoc 插件、lint、mockgen
make proto                # 生成 internal/agentproto/*.pb.go
cp deploy/conf/panel.dev.yaml conf/panel.yaml
make migrate              # 对开发库执行 migrations
make run                  # 后端 :34567，SQLite 落在 ./.dev/data
# 另开终端
make web-dev              # 前端 :5173，代理 /api 到 34567
```

开发期约定：

| 项 | 约定 |
| --- | --- |
| 开发数据目录 | `./.dev/{data,logs,conf}`，已加入 `.gitignore` |
| 默认账号 | 首次启动生成随机密码并打印到控制台，禁止内置固定弱口令 |
| TLS | 开发期自签证书由 `make certs` 生成到 `./.dev/certs` |
| 前端代理 | Vite `server.proxy` 将 `/api` 与 `/ws` 转发到 `https://127.0.0.1:34567`，`secure: false` |
| 热重载 | 后端用 `make run-watch`（air），前端 Vite HMR |

## 3.5 Makefile 与构建

```makefile
# ===== 变量 =====
APP            := novapanel
AGENT          := nova-agent
CLI            := novactl
VERSION        ?= $(shell git describe --tags --always --dirty)
COMMIT         := $(shell git rev-parse --short HEAD)
BUILD_TIME     := $(shell date -u +%Y-%m-%dT%H:%M:%SZ)
GO_VERSION     := $(shell go env GOVERSION)
LDFLAGS        := -s -w \
	-X 'main.Version=$(VERSION)' \
	-X 'main.Commit=$(COMMIT)' \
	-X 'main.BuildTime=$(BUILD_TIME)'
BIN_DIR        := bin
DIST_DIR       := dist
PLATFORMS      := linux/amd64 linux/arm64
GOFLAGS        := -trimpath
PKG            := ./...
COVER_PROFILE  := coverage.out
SERVICE_PKGS   := ./internal/service/...

.DEFAULT_GOAL := help
.PHONY: help doctor install-tools proto web web-dev build build-panel build-agent \
        build-cli run run-watch test test-cover lint fmt vet migrate certs \
        docker release audit clean tidy mocks swagger
```

```makefile
# ===== 帮助与环境自检 =====
help: ## 打印所有目标
	@grep -E '^[a-zA-Z_-]+:.*?## .*$$' $(MAKEFILE_LIST) | \
		awk 'BEGIN{FS=":.*?## "}{printf "  \033[36m%-16s\033[0m %s\n",$$1,$$2}'

doctor: ## 校验本地工具链版本
	@go version && node -v && pnpm -v && protoc --version && golangci-lint version

install-tools: ## 安装开发所需 Go 工具
	go install google.golang.org/protobuf/cmd/protoc-gen-go@v1.35.1
	go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@v1.5.1
	go install github.com/swaggo/swag/cmd/swag@v1.16.4
	go install github.com/golangci/golangci-lint/cmd/golangci-lint@v1.61.0
	go install go.uber.org/mock/mockgen@v0.5.0

# ===== 代码生成 =====
proto: ## 生成 gRPC 代码
	protoc --proto_path=api/proto \
		--go_out=paths=source_relative:internal/agentproto \
		--go-grpc_out=paths=source_relative:internal/agentproto \
		api/proto/*.proto

mocks: ## 生成接口 mock
	mockgen -source=internal/repository/interface.go -destination=internal/repository/mock/repo_mock.go -package=mock
	mockgen -source=internal/executor/interface.go   -destination=internal/executor/mock/exec_mock.go -package=mock

swagger: ## 生成 OpenAPI 3 文档
	swag init -g cmd/panel/main.go -o docs/openapi --v3.1 --parseDependency --parseInternal

# ===== 前端 =====
web: ## 构建前端并输出到 internal/api/v1/static/dist
	cd web && pnpm install --frozen-lockfile && pnpm build

web-dev: ## 启动前端开发服务
	cd web && pnpm dev

# ===== 后端构建 =====
build: build-panel build-agent build-cli ## 构建三个二进制（当前平台）

build-panel: web
```

## 3.7 Go 编码规范

### 3.7.1 命名

| 对象 | 规则 | 正例 | 反例 |
| --- | --- | --- | --- |
| 包名 | 全小写单词，无下划线无复数 | `executor`、`alerting` | `Executors`、`agent_proto` |
| 文件名 | 小写下划线，按聚合职责 | `site_service.go`、`node_repo.go` | `SiteService.go` |
| 接口 | 能力名或 `-er`，不加 `I` 前缀 | `SiteRepository`、`Notifier` | `ISiteRepo` |
| 实现结构体 | 接口名去掉后缀 + 具体实现 | `siteRepoGorm`、`dingTalkNotifier` | `SiteRepositoryImpl` |
| 方法 | 动词开头，导出方法必须有注释 | `CreateSite`、`ListByNodeID` | `DoSite`、`Handle2` |
| 常量与枚举 | 类型化常量，前缀为类型名 | `SiteStatusRunning` | `RUNNING` |
| 缩写 | 全大写或全小写，不混写 | `nodeID`、`HTTPClient` | `nodeId`、`HttpClient` |
| 上下文参数 | 首参恒为 `ctx context.Context` | `func (s *svc) Get(ctx, id)` | `func (s *svc) Get(id, ctx)` |
| 测试函数 | `Test<被测函数>_<场景>` | `TestCreateSite_DuplicateDomain` | `TestCreateSite2` |

### 3.7.2 错误处理

| 规则 | 说明 |
| --- | --- |
| 不吞错误 | 禁止 `_ = err`；确实可忽略需写注释说明理由 |
| 统一错误类型 | 跨层传递必须是 `*errs.Error`，由 `errs.New` / `errs.Wrap` 构造 |
| 只在边界转换 | repository 返回原始错误 + 语义码，service 补充业务语义，handler 只做映射，不再包装 |
| 禁止 panic | 除 `main` 初始化阶段的不可恢复错误外禁用 panic；中间件兜底 recover 并记录堆栈 |
| 错误信息面向用户 | `Message` 为可直接展示的中文，敏感细节放 `Detail`（仅日志与管理员可见） |
| 哨兵错误比较 | 用 `errors.Is`，禁止字符串匹配 |

### 3.7.3 context 传递

| 规则 | 说明 |
| --- | --- |
| 必须透传 | 从 handler 到 repository 全链路传递同一 ctx，禁止中途 `context.Background()` |
| 携带值白名单 | 仅允许 `traceID`、`userID`、`tenantID`、`nodeID`、`locale`，通过 `internal/pkg/ctxkey` 的类型化 key 存取 |
| 超时约定 | HTTP 请求默认 30s；跨节点任务由调用方显式给 deadline；后台任务用独立 ctx 并响应关停信号 |
| 异步任务 | 不得直接复用请求 ctx（请求结束即取消），须用 `context.WithoutCancel(ctx)` 派生并重设超时 |

### 3.7.4 参数校验

校验分三层，各层职责不重叠：

| 层 | 校验内容 | 手段 |
| --- | --- | --- |
| handler | 格式、必填、范围、枚举合法性 | `validator/v10` binding tag |
| service | 业务规则（域名是否已存在、节点是否在线、配额是否超限） | 显式代码 + repository 查询 |
| repository | 唯一约束、外键 | 数据库约束兜底 |

```go
// SiteCreateReq 站点创建请求，字段级校验由 binding tag 完成。
type SiteCreateReq struct {
	NodeID     int64    `json:"nodeId"     binding:"required,gt=0"`
	Name       string   `json:"name"       binding:"required,min=1,max=64"`
	Domains    []string `json:"domains"    binding:"required,min=1,max=20,dive,fqdn"`
	Type       string   `json:"type"       binding:"required,oneof=static php proxy balance"`
	RootPath   string   `json:"rootPath"   binding:"required,startswith=/,max=255,safepath"`
	PHPVersion string   `json:"phpVersion" binding:"required_if=Type php,omitempty,oneof=7.4 8.0 8.1 8.2 8.3"`
	EnableSSL  bool     `json:"enableSSL"`
	Remark     string   `json:"remark"     binding:"max=255"`
}
```

自定义校验器统一注册在 `internal/pkg/validator`：`safepath`（拒绝 `..`、拒绝敏感目录）、`cron`（cron 表达式）、`portrange`、`cidr`、`nodeselector`。

### 3.7.5 禁止事项清单

| 编号 | 禁止 | 原因 |
| --- | --- | --- |
| F1 | service 层引用 `gin` 包 | 破坏分层，无法脱离 HTTP 测试 |
| F2 | handler 直接使用 `*gorm.DB` | 绕过仓储抽象 |
| F3 | service / repository 中出现 `os/exec`、`exec.Command` | 系统调用必须走 executor |
| F4 | 字符串拼接 SQL | 注入风险，必须用 GORM 占位符 |
| F5 | 拼接 shell 命令时插入用户输入 | 命令注入；必须用参数数组形式并做白名单 |
| F6 | 使用 `time.Now()` 于可测逻辑 | 不可测；注入 `Clock` 接口 |
| F7 | 全局可变变量承载状态 | 并发不安全；用依赖注入 |
| F8 | `init()` 中做 I/O 或读配置 | 初始化顺序不可控 |
| F9 | 日志打印明文密码、token、私钥 | 泄密；统一走脱敏函数 |
| F10 | 忽略 `defer` 中的 Close 错误（写操作） | 数据可能未落盘 |
| F11 | 无边界 goroutine（`go func()` 裸启） | 泄漏；必须走 `pkg/pool` 或 errgroup |
| F12 | 在循环中查询数据库（N+1） | 性能；批量查询或预加载 |
| F13 | 使用 `panic` 控制流程 | 破坏可读性与稳定性 |
| F14 | 直接返回 GORM 错误给前端 | 泄露表结构；必须转 `*errs.Error` |
| F15 | 硬编码路径、端口、密钥 | 必须走配置项 |

文件 `internal/pkg/errs/errs.go`：

```go
// Package errs 提供全项目统一的错误类型与错误码。
// 约定：跨层传递的错误必须是 *Error；构造只能通过 New / Wrap / Newf。
package errs

import (
	"errors"
	"fmt"
	"net/http"
)

// Error 是全项目统一错误类型。
// Code 为 6 位业务错误码；Message 面向最终用户（可直接展示）；
// Detail 面向排查（仅写日志与管理员可见）；Fields 为结构化上下文。
type Error struct {
	Code    int
	Message string
	Detail  string
	Fields  map[string]any
	cause   error
}

func (e *Error) Error() string {
	if e.cause != nil {
		return fmt.Sprintf("code=%d msg=%s detail=%s cause=%v", e.Code, e.Message, e.Detail, e.cause)
	}
	return fmt.Sprintf("code=%d msg=%s detail=%s", e.Code, e.Message, e.Detail)
}

func (e *Error) Unwrap() error { return e.cause }

// Is 支持按错误码比较：errors.Is(err, errs.ErrNotFound)。
func (e *Error) Is(target error) bool {
	var t *Error
	if errors.As(target, &t) {
		return e.Code == t.Code
	}
	return false
}

// WithDetail 补充排查信息，返回副本，不修改原错误。
func (e *Error) WithDetail(format string, args ...any) *Error {
	c := *e
	c.Detail = fmt.Sprintf(format, args...)
	return &c
}

// WithField 附加结构化上下文，返回副本。
func (e *Error) WithField(key string, val any) *Error {
	c := *e
	c.Fields = make(map[string]any, len(e.Fields)+1)
	for k, v := range e.Fields {
		c.Fields[k] = v
	}
	c.Fields[key] = val
	return &c
}
```

构造与工具函数 `internal/pkg/errs/api.go`：

```go
// New 用错误码与用户可见消息构造错误。
func New(code int, message string) *Error {
	return &Error{Code: code, Message: message}
}

// Newf 同 New，message 支持格式化。
func Newf(code int, format string, args ...any) *Error {
	return &Error{Code: code, Message: fmt.Sprintf(format, args...)}
}

// Wrap 包装底层错误并赋予业务错误码。cause 为 nil 时等价于 New。
func Wrap(cause error, code int, message string) *Error {
	if cause == nil {
		return New(code, message)
	}
	var e *Error
	if errors.As(cause, &e) && e.Code == code {
		return e // 同码不重复包装，避免栈式嵌套
	}
	return &Error{Code: code, Message: message, Detail: cause.Error(), cause: cause}
}

// Code 提取业务错误码；非 *Error 返回 CodeInternal；nil 返回 0。
func Code(err error) int {
	if err == nil {
		return 0
	}
	var e *Error
	if errors.As(err, &e) {
		return e.Code
	}
	return CodeInternal
}

// Message 提取用户可见消息；非 *Error 返回通用兜底文案。
func Message(err error) string {
	var e *Error
	if errors.As(err, &e) {
		return e.Message
	}
	return "服务内部错误"
}

// HTTPStatus 将业务错误码映射为 HTTP 状态码。
func HTTPStatus(code int) int {
	if s, ok := statusMap[code]; ok {
		return s
	}
	switch code / 10000 { // 按模块兜底
	case 11, 12:
		return http.StatusForbidden
	default:
		return http.StatusBadRequest
	}
}

// 预定义哨兵错误，供 errors.Is 比较。
var (
	ErrInvalidParam = New(CodeInvalidParam, "请求参数不合法")
	ErrNotFound     = New(CodeNotFound, "资源不存在")
	ErrConflict     = New(CodeConflict, "资源状态冲突")
	ErrForbidden    = New(CodeForbidden, "无操作权限")
	ErrNodeOffline  = New(CodeNodeOffline, "目标节点离线")
	ErrInternal     = New(CodeInternal, "服务内部错误")
)
```

### 3.8.3 errs 用法示例

```go
// repository：仅赋予语义码，不写用户文案以外的业务判断
func (r *siteRepoGorm) FindByID(ctx context.Context, id int64) (*model.Site, error) {
	var s model.Site
	err := r.db(ctx).Where("id = ? AND tenant_id = ?", id, ctxkey.TenantID(ctx)).First(&s).Error
	if errors.Is(err, gorm.ErrRecordNotFound) {
		return nil, errs.ErrNotFound.WithDetail("site id=%d not found", id)
	}
	if err != nil {
		return nil, errs.Wrap(err, errs.CodeInternal, "查询站点失败")
	}
	return &s, nil
}

// service：补充业务语义与上下文字段
func (s *siteService) Delete(ctx context.Context, id int64) error {
	site, err := s.repo.FindByID(ctx, id)
	if err != nil {
		return err // 已是 *errs.Error，不重复包装
	}
	if site.Status == model.SiteStatusDeploying {
		return errs.New(errs.CodeConflict, "站点正在部署中，请稍后再试").
			WithField("siteId", id).WithField("status", site.Status)
	}
	if err := s.gw.Invoke(ctx, site.NodeID, task.RemoveVhost(site)); err != nil {
		return errs.Wrap(err, errs.CodeSiteRemoveFailed, "删除站点配置失败，已保留站点目录")
	}
	return s.repo.SoftDelete(ctx, id)
}

// handler：只做映射，不判断业务
func (h *SiteHandler) Delete(c *gin.Context) {
	id, err := strconv.ParseInt(c.Param("id"), 10, 64)
	if err != nil {
		response.Fail(c, errs.ErrInvalidParam.WithDetail("id=%q", c.Param("id")))
		return
	}
	if err := h.siteSvc.Delete(ctxutil.From(c), id); err != nil {
		response.Fail(c, err)
		return
	}
	response.OK(c, nil)

```

响应封装 `internal/api/v1/response`：`OK(c, data)`、`Page(c, list, total)`、`Fail(c, err)`。`Fail` 负责：取 `errs.Code` 与 `errs.Message`、按 `errs.HTTPStatus` 设状态码、注入 `traceId` 与 `timestamp`、把 `Detail` 与 `Fields` 写入日志而**不返回给前端**（仅 `super_admin` 且开启调试模式时附加 `debug` 字段）。

错误码登记流程：新增错误码必须同时改三处，缺一 CI 失败——`internal/pkg/errs/code.go` 常量、`statusMap` 映射、`docs/05-API接口规范.md` 错误码表；CI 用脚本 `scripts/check-errcode.sh` 比对三者一致性。

## 3.9 日志规范

### 3.9.1 输出与切割

| 项 | 约定 |
| --- | --- |
| 库 | `log/slog`（JSON handler）+ `lumberjack` 切割 |
| 文件 | `panel.log`（应用）、`access.log`（HTTP 访问）、`audit.log`（审计，独立且不可通过界面删除）、`agent.log`（被控端） |
| 切割 | 单文件 100MB、保留 10 份、压缩归档、最长保留 30 天 |
| 级别 | `debug` / `info` / `warn` / `error`；生产默认 `info`，可运行时热调（`PATCH /api/v1/system/log-level`） |
| 控制台 | 开发模式输出彩色文本，生产模式只写文件 + 可选 stdout（容器部署） |
| 采样 | 同一 `msg + module` 的 error 日志 1 分钟内最多 10 条，超出计数聚合 |

### 3.9.2 结构化字段约定

固定字段由 `logx.FromContext(ctx)` 自动注入，业务代码只补充语义字段。

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `time` | RFC3339Nano | 是 | UTC |
| `level` | string | 是 | 大写 |
| `msg` | string | 是 | 中文简述，不含变量拼接 |
| `module` | string | 是 | `site` / `cluster` / `monitor` 等，与错误码模块对应 |
| `traceId` | string | 是 | 来自 `X-Request-Id` 或自动生成 |
| `userId` | int64 | 有登录态时 | — |
| `tenantId` | int64 | 是 | 默认 1 |
| `nodeId` | int64 | 跨节点操作时 | — |
| `taskId` | int64 | 作业相关时 | — |
| `code` | int | error 级别必需 | 业务错误码 |
| `costMs` | int64 | 有耗时语义时 | 毫秒 |
| `err` | string | error 级别必需 | `errs.Error.Detail` 或原始错误 |
| `caller` | string | 是 | 自动注入 `file:line` |

```go
// 正确：msg 固定，变量进字段
logx.FromContext(ctx).Info("站点创建成功",
    "module", "site", "siteId", site.ID, "nodeId", site.NodeID, "costMs", cost.Milliseconds())

// 错误：变量拼进 msg，无法聚合统计
```

### 3.9.3 脱敏

`logx` 在序列化前对字段名命中以下模式的值一律替换为 `***`：`password`、`passwd`、`secret`、`token`、`accessKey`、`secretKey`、`privateKey`、`authorization`、`cookie`、`totp`。命令行日志额外对 `-p<密码>`、`--password=` 形式做正则脱敏。审计日志中的参数快照在写入前经同一脱敏管道，禁止绕过。

### 3.10.1 命名与文件组织

| 对象 | 规则 | 示例 |
| --- | --- | --- |

### 3.10.2 组合式 API 约定

```vue
<script setup lang="ts">
import { computed, onMounted, ref } from 'vue'
import type { NodeVO } from '@/api/cluster'
import { listNodes } from '@/api/cluster'

// 1. props / emits 显式类型化，props 必须有默认值（除必填）
interface Props {
  groupId?: number
  autoRefresh?: boolean
}
const props = withDefaults(defineProps<Props>(), {
  groupId: undefined,
  autoRefresh: true,
})
const emit = defineEmits<{
  select: [node: NodeVO]
  refreshed: [total: number]
}>()

// 2. 响应式状态集中声明在顶部
const loading = ref(false)
const nodes = ref<NodeVO[]>([])

// 3. 派生状态用 computed，禁止在 watch 里手动同步
const onlineCount = computed(() => nodes.value.filter((n) => n.status === 'online').length)

// 4. 异步逻辑抽成命名函数，不写内联匿名 async
async function fetchNodes() {
  loading.value = true
  try {
    const { list, total } = await listNodes({ page: 1, pageSize: 100, groupId: props.groupId })
    nodes.value = list
    emit('refreshed', total)
  } finally {
    loading.value = false
  }
}

onMounted(fetchNodes)
defineExpose({ refresh: fetchNodes })
</script>
```

### 3.10.3 前端禁止事项

| 编号 | 禁止 | 原因 |
| --- | --- | --- |
| FE1 | 使用 `any` 逃逸类型（`unknown` + 收窄替代） | 类型系统失效；ESLint 报错 |
| FE2 | 组件内硬编码中文文案 | 破坏 i18n；用 `t('cluster.node.title')` |
| FE3 | 直接调用 `axios`，绕过 `@/api/request` 封装 | 丢失鉴权、错误处理、traceId |
| FE4 | 在组件中直接拼接接口 URL | 接口变更无法集中修改 |
| FE5 | `watch` 中修改被监听的响应式源 | 死循环风险 |
| FE6 | 深层 props 透传（超过 2 层） | 用 provide/inject 或 store |
| FE7 | 在 store 中做 DOM 操作或路由跳转 | 职责混乱、不可测 |
| FE8 | `v-for` 用 index 作 key（列表可变时） | 复用错位导致渲染错误 |
| FE9 | 全量引入 lodash / echarts | 包体积；按需 `lodash-es` 与 echarts 按模块 |
| FE10 | `localStorage` 存 accessToken 或任何敏感值 | XSS 窃取风险 |
| FE11 | 在 `setup` 顶层写 `await`（除顶层 Suspense 场景） | 生命周期上下文丢失 |
| FE12 | 直接改 Arco 组件内部 DOM 或用 `!important` 覆盖 | 升级即碎；用主题变量与 CSS 变量 |
| FE13 | 定时器 / WebSocket / ECharts 实例未在 `onUnmounted` 释放 | 内存泄漏 |
| FE14 | 权限判断只在前端做（不请求后端） | 前端仅控制展示，后端必须再判一次 |

### 3.11.3 敏感配置加密存储

| 类别 | 存储位置 | 加密方式 |
| --- | --- | --- |
| 面板登录密码 | `sys_user.password` | bcrypt cost 12（不可逆） |
| 数据库连接密码 | `panel.yaml` 或环境变量 | 建议环境变量注入；文件形式要求 0600 |
| 对象存储密钥、DNS API 密钥、仓库凭据 | 数据库对应表字段 | AES-256-GCM，KEK 来自 `security.master_key_file` |
| 证书私钥 | `web_cert.private_key` | AES-256-GCM |
| Agent 客户端证书私钥 | 节点本地文件 0600 | 不上传控制面 |
| API 密钥 | `sys_api_key.secret_hash` | 仅存 SHA-256 哈希，明文只在创建时展示一次 |

实现方式：定义 `model.Encrypted` 类型实现 `sql.Scanner` 与 `driver.Valuer`，加解密在类型内完成，业务代码按普通字符串使用；`master.key` 首次启动自动生成 32 字节随机值，缺失则拒绝启动（避免静默降级为明文）。密钥轮换命令 `novactl rotate-key --old <file> --new <file>`，逐表重加密并支持中断续跑。

### 3.12.1 文件命名与组织

### 3.12.2 幂等与安全要求

| 要求 | 写法 |
| --- | --- |
| 建表幂等 | `CREATE TABLE IF NOT EXISTS` |
| 加列幂等 | MySQL 8.0 无 `IF NOT EXISTS`，用迁移器版本表保证只执行一次；PG/SQLite 用 `ADD COLUMN IF NOT EXISTS` |
| 建索引幂等 | `CREATE INDEX IF NOT EXISTS`（三库均支持） |
| 大表加列 | 必须可空或带默认值，禁止在 > 100 万行表上加 `NOT NULL` 无默认列 |
| 数据回填 | 分批（每批 1000 行）+ 独立迁移文件，禁止与 DDL 混在一起 |
| 删除列 | 两阶段：先停用（代码不再读写）→ 下个小版本再物理删除 |
| 破坏性操作 | `DROP TABLE` / `DROP COLUMN` 必须在 PR 描述中单独说明并经二人评审 |

```sql
-- 20260817120000_create_sys_user.up.sql
CREATE TABLE IF NOT EXISTS sys_user (
    id           BIGINT       NOT NULL,
    tenant_id    BIGINT       NOT NULL DEFAULT 1,
    username     VARCHAR(64)  NOT NULL,
    password     VARCHAR(72)  NOT NULL,
    nickname     VARCHAR(64)  NOT NULL DEFAULT '',
    email        VARCHAR(128) NOT NULL DEFAULT '',
    status       SMALLINT     NOT NULL DEFAULT 1,
    totp_secret  VARCHAR(255) NOT NULL DEFAULT '',
    fail_count   INT          NOT NULL DEFAULT 0,
    locked_until BIGINT       NOT NULL DEFAULT 0,
    created_at   TIMESTAMP    NOT NULL,
    updated_at   TIMESTAMP    NOT NULL,
    deleted_at   TIMESTAMP    NULL,
    created_by   BIGINT       NOT NULL DEFAULT 0,
    PRIMARY KEY (id)
);
CREATE UNIQUE INDEX IF NOT EXISTS uk_sys_user_tenant_username ON sys_user (tenant_id, username);
CREATE INDEX IF NOT EXISTS idx_sys_user_deleted_at ON sys_user (deleted_at);
```

### 3.12.3 执行与回滚策略

迁移器自研于 `internal/repository/migrate`，不引入第三方迁移框架（避免额外依赖）。

| 项 | 约定 |
| --- | --- |
| 版本表 | `sys_schema_migration(version BIGINT PK, name, applied_at, checksum, duration_ms)` |
| 校验和 | 记录文件 sha256；已应用文件内容变更时启动直接失败并提示 |
| 执行时机 | 启动时（`database.auto_migrate=true`）或显式 `novactl migrate up` |
| 并发保护 | 迁移前获取库级锁（MySQL `GET_LOCK`，PG `pg_advisory_lock`，SQLite 独占事务） |
| 事务 | 单文件单事务（SQLite/PG 支持 DDL 事务；MySQL DDL 隐式提交，失败需人工核对，因此 MySQL 下每文件只允许一个 DDL） |
| 失败处理 | 立即停止，不继续后续版本；打印失败版本与 SQL |
| 回滚 | `novactl migrate down --step 1`，仅允许回滚未跨小版本的迁移；跨版本回滚要求先恢复备份 |
| 升级前置 | 面板在线升级流程强制先备份数据库文件/执行 dump，再执行迁移 |
| 演练要求 | 新迁移必须在三种 driver 上各跑一次 up + down + up，CI 自动执行 |

## 3.13 Git 工作流与提交规范

### 3.13.1 分支模型

| 分支 | 来源 | 合并到 | 保护规则 | 用途 |
| --- | --- | --- | --- | --- |
| `main` | — | — | 禁止直接推送；仅接受 PR；要求 CI 全绿 + 1 名评审通过 | 可发布状态，每个提交对应一次可构建版本 |
| `develop` | `main` | `main` | 禁止直接推送 | 集成分支，日常开发目标 |
| `feature/<模块>-<简述>` | `develop` | `develop` | — | 功能开发，例 `feature/cluster-batch-exec` |
| `fix/<简述>` | `develop` | `develop` | — | 非紧急缺陷修复 |
| `hotfix/<简述>` | `main` | `main` + `develop` | 需 2 名评审 | 生产紧急修复 |
| `release/v<x.y.z>` | `develop` | `main` + `develop` | 只接受修复类提交 | 发布准备与回归 |

```text
main      ─●──────────────●───────────────●──────>  (v1.0.0)      (v1.0.1)   (v1.1.0)
            \            /  \            /        /
release      \      ●──●    \      ●──●          /
              \    /         \    /             /
develop     ───●──●───●───●───●──●───●───●─────●
                   \     /         \     /
feature             ●───●           ●───●
```

### 3.13.2 Conventional Commits

格式：`<type>(<scope>): <subject>`，subject 用中文、不超过 50 字、不加句号。

| type | 用途 | 是否进 CHANGELOG |
| --- | --- | --- |
| `feat` | 新功能 | 是（Features） |
| `fix` | 缺陷修复 | 是（Bug Fixes） |
| `perf` | 性能优化 | 是（Performance） |
| `refactor` | 重构（不改行为） | 否 |
| `docs` | 文档 | 否 |
| `test` | 测试 | 否 |
| `build` | 构建脚本、依赖 | 否 |
| `ci` | 流水线 | 否 |
| `chore` | 杂项 | 否 |
| `style` | 格式（不改逻辑） | 否 |
| `revert` | 回滚 | 是 |

`scope` 白名单：`panel`、`agent`、`cli`、`api`、`service`、`repo`、`executor`、`collector`、`alerting`、`security`、`web`、`deploy`、`docs`、`migrations`、`proto`。

```text
# 正例
feat(cluster): 支持按标签选择节点批量执行命令
fix(security): 修复 refreshToken 旋转后旧 jti 未失效的问题
perf(collector): 指标批量写入改为单事务，写入耗时下降 60%
feat(api)!: 移除 /api/v1/nodes 兼容路由

BREAKING CHANGE: 请改用 /api/v1/cluster-nodes

# 反例
更新代码                      # 无 type、无信息量
feat: 修了一堆 bug            # type 与内容不符、含糊
fix(cluster): fix bug.        # 英文 + 句号 + 无信息量
```

破坏性变更用 `!` 标记并在 body 写 `BREAKING CHANGE:`，触发主版本号递增。

### 3.13.4 Code Review 检查清单

| 分类 | 检查项 |
| --- | --- |
| 分层 | handler 无业务逻辑；service 无 `gin` / `os/exec`；repository 无业务判断 |
| 安全 | 用户输入是否校验；SQL 是否参数化；shell 是否参数数组；敏感字段是否加密；日志是否脱敏 |
| 权限 | 新接口是否声明权限标识；是否注入 `tenant_id`；`auditor` 是否被正确拦截 |
| 错误 | 是否返回 `*errs.Error`；错误码是否登记；用户文案是否可读 |
| 并发 | 是否有裸 goroutine；共享状态是否有锁；ctx 是否透传 |
| 性能 | 是否有 N+1 查询；是否缺索引；是否有无界内存增长 |
| 可测 | 是否依赖真实时间/随机数/网络；接口是否可 mock |
| 审计 | 写操作是否记审计；变更前后是否留快照 |
| 兼容 | 是否改了已有接口契约；是否影响低版本 Agent；迁移是否可回滚 |
| 前端 | 是否有硬编码文案；组件是否释放资源；是否处理 loading 与错误态；权限是否控制展示 |

### 3.13.5 语义化版本与 CHANGELOG

| 变更 | 版本位 | 示例 |
| --- | --- | --- |
| 破坏性变更（API 契约、配置键删除、数据库不可回滚） | MAJOR | 1.2.3 → 2.0.0 |
| 新功能、新增可选配置项、新增接口 | MINOR | 1.2.3 → 1.3.0 |
| 缺陷修复、性能优化、文档 | PATCH | 1.2.3 → 1.2.4 |

Agent 与控制面版本兼容承诺：同一 MINOR 内完全兼容；控制面可管理比自身低一个 MINOR 的 Agent（能力协商后降级）；Agent 版本高于控制面时拒绝注册并提示。

CHANGELOG 由 `git-chglog` 依据 Conventional Commits 自动生成，人工补充「升级注意事项」段落；发布 tag 格式 `v1.0.0`，预发布 `v1.1.0-rc.1`。

### 3.14.3 pre-commit hook

`scripts/git-hooks/pre-commit`（由 `make install-tools` 软链到 `.git/hooks/`）：

```bash
#!/usr/bin/env bash
set -euo pipefail

STAGED_GO=$(git diff --cached --name-only --diff-filter=ACM | grep -E '\.go$' || true)
STAGED_WEB=$(git diff --cached --name-only --diff-filter=ACM | grep -E '^web/.*\.(ts|vue|scss)$' || true)
FAIL=0

# 1. 阻止提交敏感文件与大文件
if git diff --cached --name-only | grep -E '(^|/)(\.env|master\.key|.*\.pem|.*\.key)$'; then
  echo "[pre-commit] 检测到敏感文件，禁止提交"; FAIL=1
fi
while read -r f; do
  [ -z "$f" ] && continue
  size=$(git cat-file -s ":$f" 2>/dev/null || echo 0)
  if [ "$size" -gt 2097152 ]; then echo "[pre-commit] $f 超过 2MB"; FAIL=1; fi
done < <(git diff --cached --name-only --diff-filter=ACM)

# 2. Go：格式化 + 快速静态检查
if [ -n "$STAGED_GO" ]; then
  gofmt -l $STAGED_GO | tee /tmp/nova-fmt.txt
  [ -s /tmp/nova-fmt.txt ] && { echo "[pre-commit] 请先执行 make fmt"; FAIL=1; }
  golangci-lint run --fast --new-from-rev=HEAD || FAIL=1
  go build ./... || FAIL=1
fi

# 3. 前端：lint + 类型检查（仅在前端有变更时）
if [ -n "$STAGED_WEB" ]; then
  (cd web && pnpm exec eslint $(echo "$STAGED_WEB" | sed 's|^web/||') --max-warnings 0) || FAIL=1
  (cd web && pnpm typecheck) || FAIL=1
fi

# 4. 错误码三处一致性
if git diff --cached --name-only | grep -qE 'errs/code\.go|05-API接口规范\.md'; then
  ./scripts/check-errcode.sh || FAIL=1
fi

exit $FAIL
```

配套 `commit-msg` hook 校验 Conventional Commits 格式与 scope 白名单，不符则拒绝提交。

```yaml
          [ "$MAIN_GZ" -le 512000 ] || { echo "主包超过 500KB"; exit 1; }
      - name: 交叉编译
        run: |
          for c in panel:novapanel agent:nova-agent novactl:novactl; do
            CGO_ENABLED=0 GOOS=linux GOARCH=${{ matrix.goarch }} \
              go build -trimpath -ldflags "-s -w" -o bin/${c#*:} ./cmd/${c%:*}
          done
      - uses: actions/upload-artifact@v4
        with: { name: bin-linux-${{ matrix.goarch }}, path: bin/ }
```

`.goreleaser.yaml` 关键约定（完整文件见仓库）：

| 配置项 | 取值 | 说明 |

## 3.16 国际化文案规范

### 3.16.1 key 命名

格式：`<模块>.<页面或组件>.<语义>`，全小写，层级用点，语义部分用小驼峰。

| 类别 | 格式 | 示例 |
| --- | --- | --- |
| 页面标题 | `<模块>.<页面>.title` | `cluster.node.title` |
| 表格列名 | `<模块>.<页面>.column.<字段>` | `cluster.node.column.agentVersion` |
| 表单标签 | `<模块>.<页面>.field.<字段>` | `web.site.field.rootPath` |
| 按钮 | `common.action.<动作>` 或模块专属 | `common.action.confirm`、`cluster.node.action.batchExec` |
| 提示与确认 | `<模块>.<页面>.tip.<语义>` | `bak.policy.tip.restoreDanger` |
| 校验消息 | `<模块>.<页面>.valid.<字段>` | `web.site.valid.domainInvalid` |
| 枚举文案 | `enum.<枚举名>.<值>` | `enum.nodeStatus.online` |
| 错误码文案 | `error.<错误码>` | `error.200021` |
| 通用词 | `common.<语义>` | `common.status`、`common.createdAt` |

### 3.16.2 文件组织

```text
web/src/locales/
├── index.ts                 # createI18n 装配、语言检测、懒加载
├── zh-CN/
│   ├── common.json
│   ├── enum.json
│   ├── error.json           # 由脚本从后端错误码表生成，禁止手改
│   ├── cluster.json
│   ├── web.json
│   ├── ct.json
│   ├── mon.json
│   └── ...                  # 每个业务模块一个文件，与路由模块一一对应
└── en-US/                   # 结构与 zh-CN 完全镜像
    └── ...
```

| 规则 | 说明 |
| --- | --- |
| 文件镜像 | 各语言目录文件名与 key 结构必须完全一致，CI 用 `scripts/check-i18n.mjs` 校验差异为 0 |
| 插值 | 用命名占位符 `{count}`、`{name}`，禁止位置占位符 |
| 复数 | 用 vue-i18n 复数语法，英文必须处理单复数 |
| 富文本 | 禁止在文案中写 HTML；需要强调时拆成多个 key 由模板组合 |
| 长度 | 英文文案通常比中文长 30%-50%，UI 需按英文宽度设计，按钮不得因换行破版 |
| 后端文案 | 错误消息由后端按语言返回；前端仅在后端未提供时用 `error.<code>` 兜底 |
| 新增流程 | 先加 `zh-CN`，同一 PR 内必须补 `en-US`（可为初译，标注 `// TODO: review`） |
| 禁止 | 组件内出现中文字面量（ESLint 自定义规则 `no-chinese-literal` 拦截，注释与测试除外） |

## 3.17 文档与注释规范

### 3.17.1 Go 注释

| 对象 | 要求 |
| --- | --- |
| 包 | 每个包在一个文件顶部写 `// Package xxx ...`，说明职责与使用约束 |
| 导出标识符 | 必须有注释，以标识符名开头，中文描述 |
| 接口方法 | 说明语义、错误返回可能的错误码、是否幂等 |
| 复杂逻辑 | 说明「为什么这么做」，不重复「做了什么」 |
| TODO | 格式 `// TODO(用户名, YYYY-MM-DD): 说明`，CI 统计但不阻断；超过 90 天的 TODO 进技术债看板 |
| 禁止 | 注释掉的死代码（直接删，靠 Git 找回） |

### 3.17.2 swag 注解写法

`main.go` 全局定义：

```go
// @title                      NovaPanel OpenAPI
// @version                    1.0
// @description                星舵面板控制面接口。所有接口统一返回 {"code","message","data","traceId","timestamp"}。
// @termsOfService              https://novapanel.io/terms
// @contact.name                NovaPanel Team
// @license.name                Apache 2.0
// @host                       localhost:34567
// @BasePath                   /api/v1
// @schemes                    https
// @securityDefinitions.apikey BearerAuth
// @in                         header
// @name                       Authorization
// @description                格式：Bearer <accessToken>
func main() { /* ... */ }
```

接口注解模板（每个 handler 必须完整填写，缺失导致 CI 的 swag 校验失败）：

```go
// ListNodes 分页查询集群节点
// @Summary      分页查询集群节点
// @Description  支持按分组、标签、状态过滤；keyword 匹配节点名与 IP。
// @Tags         集群节点
// @Accept       json
// @Produce      json
// @Param        page      query     int     false  "页码"          default(1)   minimum(1)
// @Param        pageSize  query     int     false  "每页条数"       default(20)  maximum(200)
// @Param        keyword   query     string  false  "关键字"
// @Param        sort      query     string  false  "排序字段"       Enums(created_at, name, status)
// @Param        order     query     string  false  "排序方向"       Enums(asc, desc)  default(desc)
// @Param        groupId   query     int     false  "分组 ID"
// @Param        status    query     string  false  "节点状态"       Enums(online, unstable, offline)
// @Success      200  {object}  response.PageResult[model.NodeVO]
// @Failure      400  {object}  response.Result[any]  "100001 参数不合法"
// @Failure      401  {object}  response.Result[any]  "110001 未登录"
// @Failure      403  {object}  response.Result[any]  "120003 无权限 cluster:node:list"
// @Router       /cluster-nodes [get]
// @Security     BearerAuth
func (h *NodeHandler) ListNodes(c *gin.Context) { /* ... */ }
```

| 约定 | 说明 |
| --- | --- |
| `@Tags` | 用中文模块名，与 [API 接口规范](./05-API接口规范.md) 的分组一致 |
| `@Router` | 路径不含 `/api/v1` 前缀（由 `@BasePath` 提供） |
| `@Failure` | 必须列出该接口所有可能的业务错误码，注释中写「码 + 中文说明」 |
| 权限标识 | 在 `@Failure 403` 描述里写出所需权限标识，便于前端与测试对照 |
| 节点相关接口 | 必须声明 `@Param X-Node-Id header int64 true "目标节点 ID"` |
| 生成 | `make swagger` 输出到 `docs/openapi`，产物提交到仓库以便离线查阅 |
| 校验 | CI 执行 `swag init` 后比对 git diff，有差异说明未同步，阻断 |

### 3.17.3 前端注释与文档

| 对象 | 要求 |
| --- | --- |
| 组合式函数 | JSDoc 说明参数、返回值、副作用与清理时机 |
| 复杂组件 | SFC 顶部块注释说明用途、props 语义、事件时序 |
| API 函数 | 说明对应后端路径与所需权限标识 |
| 类型 | 与后端 DTO 对应的类型注明来源接口，字段含义与后端文档一致 |
| 禁止 | 用注释替代命名（`// 临时变量 a` 说明命名有问题，应改名） |
